# AI 宠物项目 · 教师讲义

## 一、课程定位

| 项目 | 说明 |
|---|---|
| 学生起点 | 零编程基础 |
| 教学目标 | 学会"用 AI 做出一个产品"的完整流程：想清楚 → 让 AI 实现 → 测试 → 修改 → 发布 |
| 最终作品 | 每人一只自己设计的 AI 宠物，有公开网址，手机可玩 |
| 建议课时 | 6 次课，每次 90 分钟；视频生成可布置为课后作业 |

**这门课不教编程语法。** 学生的代码由 AI 写，学生要学的是：做决定、描述需求、验收结果、发现问题、推动修改。这些能力换任何工具都用得上。

## 二、课前准备

### 老师要做的

1. **自己先完整做一遍**（约 3～4 小时），熟悉每个阶段会遇到的情况。
2. **准备好模板项目的下载地址**，发给学生。
3. **确认教室网络**：
   - 能访问 npm（或改用国内镜像 npmmirror）。
   - 能访问学生选用的模型平台。
   - 手机和电脑能在同一个 WiFi 下互相访问。很多学校网络禁止设备互访，这种情况下请学生用手机热点。
4. **提前一周通知学生注册账号**：AI 编程工具、模型平台（需要手机号实名并充值）、AI 画图和视频工具。现场注册常因验证码、实名、支付卡住。

### 学生要准备的

见项目 `README.md` 的"开始之前你需要"。

### 费用参考（每人）

| 项目 | 大约费用 |
|---|---|
| 大模型（DeepSeek） | 充 10 元，整个课程用不完 |
| AI 画图 | 多数工具有免费额度 |
| AI 视频（8 段，各约 6 秒） | 看工具，部分有免费额度；不满意要重新生成，预留 2～3 倍的量 |
| 部署（Vercel） | 免费 |
| AI 编程工具 | 看学生使用的工具 |

## 三、课程安排

每次课的结构建议：**10 分钟讲解 → 70 分钟学生和 AI 一起做 → 10 分钟分享**。

| 课次 | 阶段 | 学生产出 | 老师重点讲 |
|---|---|---|---|
| 1 | 0 准备环境、1 设计宠物 | 环境装好；宠物设定写好 | 什么是"产品设定"；为什么先想清楚再动手 |
| 2 | 2 第一次跑起来、3 接入 AI | 能和宠物真正聊天 | 什么是 API 密钥，为什么不能泄露；提示词如何决定 AI 的性格 |
| 3 | 4 画出形象、5 让宠物动起来（开始） | 形象图；开始生成视频 | 为什么用视频而不用 3D（"先验证效果再投入"）；怎么挑合格的视频 |
| 课后 | 5 生成全部视频 | 8 段视频 | |
| 4 | 5 校准视频、6 声音 | 宠物能动、能摸、会叫 | "简单方法解决问题"：声音互动为什么不做语音识别 |
| 5 | 7 手机测试 | 测试清单全部通过 | 测试的意义；怎样把问题描述清楚 |
| 6 | 8 发布上线、9 复盘、作品展示 | 公开网址；产品介绍 | 发布前要考虑什么（费用、安全、访问口令）；回顾整个流程 |

## 四、每个阶段的验收标准

课上巡视时可以用这张表快速检查学生进度。

| 阶段 | 验收标准 |
|---|---|
| 0 | `npm run build` 成功 |
| 1 | `src/pet.config.ts` 里的设定和台词都符合学生的宠物 |
| 2 | 浏览器能打开页面，按钮台词正确 |
| 3 | 聊天回复来自真模型，有性格；密钥只在 `.env` 里 |
| 4 | `design/` 里有一张竖版半身像 |
| 5 | 视频切换正常；`?debug` 下蓝圈对准宠物的五官和身体（没有耳朵或鼻子的角色可以关闭对应分区） |
| 6 | 对宠物说话后能听到叫声 |
| 7 | 手机上测试清单全部通过 |
| 8 | 手机流量下能打开公开网址并正常聊天 |
| 9 | `README.md` 开头有学生自己写的产品介绍 |

## 五、常见问题与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `node` 命令找不到 | 没装 Node.js，或装完没重启 AI 工具 | 装 LTS 版，重启工具 |
| `npm install` 卡住 | 网络 | 加 `--registry=https://registry.npmmirror.com` |
| 聊天回复"脑袋转不动了" | 密钥错、余额不足、模型名错 | 让 AI 看终端里 `[pet-api]` 开头的报错 |
| 学生把密钥发在了聊天里 | | 立刻去平台作废并重新生成；这是一个很好的教学时机 |
| 视频切换时画面跳动 | 镜头动了，或首尾姿势不一致 | 重新生成，或让 AI 裁剪片段 |
| 手机打不开测试地址 | 不在同一 WiFi，或学校网络禁止设备互访 | 用手机热点 |
| 手机上麦克风、摄像头没反应 | 没用 `https`，或拒绝过权限 | 用 `npm run dev:https`；在浏览器设置里重新允许 |
| 线上网址打不开 | `vercel.app` 在部分网络下被限制 | 换网络测试；绑定自定义域名 |
| AI 一口气做了好几个阶段 | 部分 AI 工具不够"听话" | 让学生说"一步一步来，每步做完停下来等我" |
| AI 说"已经帮你注册好了"之类 | AI 编造了它做不到的事 | 提醒学生：账号、密钥、生成视频只能自己做，AI 说做了也要自己核实 |

## 六、评价建议

不建议只看作品好不好看。建议按下面四项评分：

| 维度 | 看什么 | 占比 |
|---|---|---|
| 产品设定 | 宠物有没有清晰的性格；台词、形象、声音是否统一 | 25% |
| 完成度 | 验收标准完成了几项；是否成功上线 | 30% |
| 测试与修改 | 是否在手机上认真测试；发现了什么问题、怎么解决的（看 `PROGRESS.md`） | 25% |
| 复盘 | 第 9 阶段五个问题的回答质量 | 20% |

## 七、可以布置的拓展任务

做完基础流程的学生，可以挑一个新功能，按同样的流程自己完成：

- 给宠物加一个新的动作和对应的视频，比如"跳舞"。
- 宠物会记住主人的生日，到那天主动祝福。
- 每天第一次打开时，宠物会说早安或晚安。
- 换一套配色，让页面风格和宠物更搭。
- 让宠物"看懂"摄像头画面：拍照发给能看图的模型，让它评论看到的东西。需要使用支持图片的模型，并考虑照片上传的隐私问题。

## 八、关于这个模板

这个模板来自一个真实的制作过程。项目里的 `skills/ai-pet-builder/references/pitfalls.md` 记录了当时实际踩过的坑，**课前值得通读一遍**，很多课上遇到的问题都能在里面找到答案。
